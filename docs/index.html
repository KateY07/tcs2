Run things
on another PC.

TCS is a tiny encrypted remote-control pair for Windows: tcs on your machine, tcsd on the other. No sshd, no .NET runtime, no accounts. Just Ed25519 keys, a fingerprint you confirm once, and one command.

PowerShell · tcs

Small, direct, scriptable

Everything you need to drive a second Windows machine from a script, a terminal or an agent, and nothing you have to babysit.

One pair of binaries

tcs controls, tcsd listens. NativeAOT builds: no runtime to install, no service to register, about 9 MB each.

Mutual key authentication

OpenSSH-format Ed25519 keys on both sides. Pair in a minute with a one-time code; the controlled host proves itself first and its key is pinned for you.

Encrypted transport

Ephemeral X25519 key agreement, HKDF-derived session keys and ChaCha20-Poly1305 for every frame.

Run Python remotely

exec sends source (or a file) to the controlled PC and returns its output and exit code. Health checks and file uploads too.

Output made for scripts

Success prints only the remote stdout. The exit code is the remote exit code. Long output is capped, never flooding your context.

Fixed paths, no overrides

Keys, trust records and data live in fixed per-user locations. There are no path flags to misconfigure or to abuse.

Four steps from zero to connected

Keys stay on the machine that made them. Only a small public pairing file travels.

Make keysOne key pair per role, no passphrase.ssh-keygen -t ed25519 -f ~\.ssh\id_ed25519
InstallRun the installer on both PCs. It shows progress and checks your key first.tcs-manual-*.exe
PairShow a one-minute code on the controlled PC, type it on the controller.tcsd pair tcs pair office-pc 481937
ConnectKeep tcsd running, then use tcs. Pairing is only open for a minute after tcsd pair.tcs office-pc health

Pair with a one-minute code

No files to move, no restart, no 43-character fingerprint to compare by eye. The controlled PC shows a short code; the controller types it. Both sides end up trusting each other.

# on the controlled PC: start tcsd with temporary pairing allowed
tcsd pair
tcsd: pairing code 481937 (valid 60 s, 3 attempts, single use)

# on the controller
tcs pair office-pc 481937
Paired with office-pc:10122
Host fingerprint: SHA256:q3Zk...
This controller is authorized there. Try: tcs office-pc health
AuthenticationSPAKE2 password-authenticated key exchange on P-256 (RFC 9382 construction). A wiretapper or man in the middle gets one online guess per session and nothing to crack offline.
WindowOpened only by starting tcsd with tcsd pair on the controlled PC; pairing is off otherwise. 60 seconds, 3 attempts, single use; then it locks.
Rate limitsOne attempt per 2 s per address. The first wrong code is forgiven as a typo; the second makes tcsd ignore that address silently for a minute (no reply at all), the third for ten. One pairing at a time, a fixed slow-down on every failure.
ResultThe controller key is authorized at once (no restart); the host key is pinned on the controller.
Exit codes0 paired, 10 not pairing, 11 bad code, 12 locked, 13 rate limited, 14 busy, 15 expired, 16 protocol error, 18 no response (silently ignored). Add --json for a structured result.

A CLI that stays out of the way

Quiet on success, loud only when something is wrong. The exit code tells scripts the rest.

# health check
tcs office-pc health
# run Python source, or a local file
tcs office-pc exec "print(1)"
tcs office-pc exec --file job.py
# upload a file (saved beside the daemon's data)
tcs office-pc upload report.txt
# more control
tcs office-pc exec "..." --max-output 0 --meta --json
successstdout holds only the remote stdout; stderr is empty; exit code 0.
remote failureRemote stderr as is, the remote exit code, and one line such as tcs: exit=3.
timeoutExit code 124 and tcs: timeout. Default limit 30 s; longer jobs are yours to follow up.
tcs errorsExit code 255 plus one line, so they never collide with a remote script's code.
--max-output NCharacters kept per stream (default 16000, head and tail, 0 = unlimited).
--json / --metaFull JSON result, or an always-on timing line.

Good to know

TCS is deliberately small. These are the edges worth reading before you rely on it. All messages are in English so scripts and agents can parse them.

exec is remote code executionThat is its job. Only add keys you control to authorized_keys, and keep private keys on the machine that made them. They are never packaged or copied.
Python on the controlled PCexec needs a Python interpreter there (or pass tcsd --python). Health checks and uploads work without it.
Trust is explicitA changed host fingerprint is refused, never auto-accepted. An unauthorized controller gets a clear NOT_AUTHORIZED reply, and a newly paired or imported key works without restarting tcsd.
Everything is auditedtcsd writes JSON lines: connections, denials (source address and controller fingerprint), pairing windows and every attempt, exec with a SHA-256 of the script (never its text). Rotated at 5 MB. Read it with tcsd audit --tail 20.
About the pairing codeSix digits are safe here only because guessing is online and limited: 3 attempts per 60-second window. Treat the code like a one-time password and do not read it out where others can hear. The SPAKE2 implementation follows the RFC but has not had an independent audit.
Keys without passphrasesPassphrase-protected keys and ssh-agent are not supported yet. Protect the .ssh folder with normal Windows account permissions.
Open the port yourselfThe installer does not touch the firewall or register a service. Allow TCP 10122 deliberately (Windows may ask when tcsd first listens), and start tcsd when you need it.
